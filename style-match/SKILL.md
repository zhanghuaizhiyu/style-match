# Style Match · 风格分析与迁移

把图片的视觉风格提炼成一份可复用的「风格DNA档案」（风格元素 + 冷暖色占比 + 氛围标签 + 简约/繁华评分），支持单图分析、多图共性归纳，以及把档案风格迁移到新图片上。

## 五种模式（按用户意图自动判断）

| 模式 | 触发场景 | 输出 |
|---|---|---|
| **A 单图分析** | 发一张图，问"什么风格/冷暖/氛围/简约还是繁华" | 该图的风格DNA档案 |
| **A+ 元素识别** | 发一张图，问"这张图有哪些内容元素/帮我区分元素" | 元素清单（含每个元素的风格速写） |
| **B 多图归纳** | 发多张图，问"共同点/共同风格/帮我总结" | 共性风格DNA档案 + 各图差异说明 |
| **C 风格迁移** | 发风格参考图/已有档案 + 一张目标照片，要求"套用这种风格" | 逐元素对应迁移后的新图片（附元素映射表） |
| **C+ 元素级迁移** | 指定"把参考图的元素X风格迁移到目标图" | 只改变元素X的新图片 |

各模式可以连续执行：先识别/分析/归纳 → 用户确认 → 再迁移。

## Step 1 · 生成风格DNA档案

用 `Read` / `ViewImage` 读取图片，按下表提取并量化，输出结构化档案：

```
【风格DNA档案】
1. 元素风格：渲染体系（写实/水彩/油画/赛璐珞/像素/3D…）、线条特征、光影处理、主体材质质感
2. 冷暖色占比：暖色 X% / 冷色 Y% / 中性色 Z%（视觉估算）
   主色调（近似 hex）：2~4 个，标明冷暖属性
   色彩关系：互补对比 / 同色系 / 高饱和 / 低饱和…
3. 氛围标签：3~5 个（如 温馨、清冷、复古、赛博、治愈、神秘、热闹、宁静…）
4. 简约-繁华度：1~10 分（1=极简，10=极繁华）
   + 依据：元素密度、画面留白比例、信息层次数量
5. 一句话总结：把以上浓缩成一段可直接当绘画提示词用的风格描述
```

**量化须知**：占比和评分是视觉估算而非精确统计，向用户说明存在误差；评分给出依据，避免拍脑袋。

## Step 2 · 多图共性归纳

1. 逐张建档（Step 1）。
2. **求交集**：冷暖占比区间取共同段、氛围标签取共同项、繁简评分取共同区间，提炼共同的主色调与色彩关系。
3. 输出「共性风格DNA档案」+ 简短的各图差异说明（哪些维度不一致、为什么）。
4. **冲突处理**：若各图在某维度差异过大（如一半极简一半极繁华），如实告知无法归纳为统一风格，列出分歧点，让用户决定剔除哪张或放宽标准。

## Step 3 · 风格迁移（默认逐元素执行）

整体迁移**不是**把参考图的整体氛围糊到目标图上，而是**逐元素对应迁移**：

1. **元素识别**：用 Step 4 的元素识别方法，分别列出参考图与目标图的内容元素清单。
2. **建立元素映射表**：参考图元素 ↔ 目标图元素逐一对应（天空↔天空、海/水面↔海/水面、岩壁/山体↔岩壁/山体、生物/人物↔生物/人物…）。目标图有而参考图没有的元素：按整体风格DNA + 语义最接近的元素风格推断处理，并向用户说明这一推断。
3. **逐元素提取风格DNA**：对每个对应元素单独提取——天空看云的概括方式与色彩、海看水面笔触与反光处理、岩壁看块面结构与详略、生物看形体概括与光影。
4. **逐元素构建提示词**：提示词按元素分段组织，每段写清"目标图中某位置的某元素，套用参考图对应元素的某风格"；以下整体约束作为总纲放在开头：
   - 保持目标图构图、主体、轮廓不变，严禁描述目标图具体内容（用 "the exact same composition and subject from the reference image" 锁定图案）
   - **简约度贴合**：按档案的简约-繁华评分控制细节量——低分时只保留主要轮廓和大块面，删除细碎线条（裂纹、碎石、细密纹理）；**删细碎 ≠ 抹平结构**：主体仍需保留可读的体块结构（层理、棱面、大裂缝与明暗阴影面）——先删到位，再按用户反馈往回补结构，每次只调一个变量
   - 结尾加画质关键词
5. **执行**：`ImageGen`——有风格参考图时 `image1`=风格参考图、`image2`=目标图（最多再传一张代表性参考图做 `image3`）；只有档案时仅传目标图靠提示词驱动；`size` 按目标图比例取最接近值（横图 `1536x1024`，竖图 `1024x1536`）
6. **逐元素校验**：生成后逐元素比对——天空是否用了参考图对云的处理、海面笔触与反光是否对齐、岩壁详略是否对齐、生物形体是否保留；未对齐的元素单独指出并单变量重试。交付时附元素映射表和各元素对齐情况。

模式 C+（只迁移单个元素）是本流程的特例：映射表只保留用户指定的元素对，其余元素在提示词中明确"保持原样"。

**迭代原则**：效果不理想时每次只调一个变量——图案变形→强化"保持原图不变"；风格偏移→补充遗漏特征；色彩不对→调整冷暖描述权重。

## Step 4 · 元素识别与元素级迁移

### 元素识别（模式 A+）

1. 用 `ViewImage` 读图，穷举列出画面中所有**内容元素**并逐一区分命名（如：公路、天空、云朵、太阳、海洋、汽车、人物、护栏…）。
2. 按层次归类：前景主体 / 中景 / 背景环境 / 光效，并标注每个元素的大致位置。
3. 每个元素附一句风格速写（材质、颜色、光影表现）。
4. 输出元素清单让用户确认，作为元素级迁移的映射基础。

### 元素级迁移（模式 C+）

用户指定映射关系，如"把参考图的『岩壁』元素风格迁移到目标图"：

1. **映射确认**：确认参考图元素 X 与目标图对应元素 Y 的语义对应关系（两图元素名不一致时先问用户，不擅自映射）。
2. **提取元素 X 的风格**：只针对元素 X 提取风格DNA（材质、色彩、笔触、详略处理），可复用档案中已有的该元素描述。
3. **构建元素级提示词**：
   - 明确指令：只替换目标图中元素 Y 的渲染风格，**其余所有元素（构图、主体、天空、水面等）保持原样不变**
   - 元素 X 的风格描述完整注入，并描述元素 Y 在目标图中的位置以帮助定位
   - 遵循「简约度贴合」和「删细碎 ≠ 抹平结构」规则
4. **执行**：`ImageGen`，`image1` = 参考图（提供元素 X 风格），`image2` = 目标图；只有风格档案时仅传目标图靠提示词驱动。
5. **校验**：检查非目标元素是否被误改；若元素边界被破坏（如迁移岩壁风格时海面也被改），指出该问题并单变量重试。


## 输出格式

- 模式 A：风格DNA档案（完整版）
- 模式 A+：元素清单（按层次归类 + 每元素风格速写）
- 模式 B：共性档案 + 差异说明
- 模式 C：风格档案摘要 + 生成图片 + 关键处理点
- 模式 C+：元素映射关系说明 + 生成图片 + 未受影响元素清单确认
- 档案用代码块包裹，便于用户复制留存、后续直接喂给模式 C/C+ 复用

## 本机工具映射

| 操作 | WorkBuddy 调用 |

| 读图分析 | `Read` / `ViewImage` |
| 风格迁移生图 | `ImageGen`（约 5–10 credits/张，批量前先告知费用） |

## 边界情况

- **只发一张图要求迁移**：询问风格来源（用该图自身？还是等下一张？），不擅自猜测
- **多图风格冲突大**：见 Step 2 第 4 条，不强行归纳
- **目标图与风格跨度极大**（如写实照片→像素风）：优先保图案还原，风格允许妥协，并提前告知
- **用户只想看分析、不想生图**：只输出档案，不调用 ImageGen

## 与 image-style-fusion 的分工

- `image-style-fusion`：两张图直接合成，快，但只认"图一风格→图二图案"，不产出量化档案，也不支持多图归纳
- `style-match`（本 skill）：先分析量化、可归纳多图共性、档案可留存复用，适合"说不清风格但想复用"和"多张参考图取共同风格"的场景

两者冲突时：用户明确提到"分析/冷暖占比/氛围/共同点/简约繁华"→ 本 skill；只说"把图一风格套到图二"→ image-style-fusion。
